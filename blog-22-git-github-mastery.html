Setting Up Git

# Install Git # macOS: brew install git # Ubuntu/Debian: sudo apt-get install git # Windows: Download from git-scm.com # Configure Git git config --global user.name "Your Name" git config --global user.email "your.email@example.com" # Set default branch name git config --global init.defaultBranch main # Configure default text editor git config --global core.editor "code --wait" # VS Code git config --global core.editor "nano" # Nano # Check configuration git config --list # Set up SSH keys for GitHub ssh-keygen -t ed25519 -C "your.email@example.com" eval "$(ssh-agent -s)" ssh-add ~/.ssh/id_ed25519 cat ~/.ssh/id_ed25519.pub # Copy this to GitHub # Test SSH connection ssh -T git@github.com # Initialize a new repository git init my-project cd my-project # Or clone an existing repository git clone https://github.com/username/repository.git git clone git@github.com:username/repository.git # SSH

Basic Git Workflow

# Check repository status git status # Add files to staging area git add filename.txt git add . # Add all files git add *.js # Add all JavaScript files git add src/ # Add entire directory # Remove files from staging area git reset filename.txt git reset # Remove all files from staging area # Commit changes git commit -m "Add new feature" git commit -am "Fix bug in login" # Add and commit in one step # View commit history git log git log --oneline git log --graph --oneline --all git log --author="Your Name" git log --since="2024-01-01" # View specific commit git show commit-hash git show HEAD git show HEAD~1 # Compare commits git diff # Working directory vs staging area git diff --staged # Staging area vs last commit git diff HEAD # Working directory vs last commit git diff commit1 commit2 # Compare two commits # Unstage files git reset HEAD filename.txt # Discard changes in working directory git checkout -- filename.txt git restore filename.txt # Git 2.23+ # Undo commits git reset --soft HEAD~1 # Keep changes staged git reset --mixed HEAD~1 # Keep changes unstaged git reset --hard HEAD~1 # Discard all changes

Working with Remotes

# Add remote repository git remote add origin https://github.com/username/repository.git git remote add upstream https://github.com/original-owner/repository.git # List remotes git remote -v # Fetch from remote git fetch origin git fetch --all # Pull changes (fetch + merge) git pull origin main git pull --rebase origin main # Push changes git push origin main git push -u origin main # Set upstream branch git push --all origin # Push all branches # Push with force (use carefully) git push --force-with-lease origin main # View remote branches git branch -r # Track remote branch git checkout -b feature-branch origin/feature-branch # Delete remote branch git push origin --delete feature-branch git push origin :feature-branch

🌳 Branching Strategies

Master branching strategies for parallel development, feature development, and release management. Learn about Git Flow, GitHub Flow, and modern branching practices.

Branch Management

# Create and switch to new branch git checkout -b feature/user-authentication git switch -c feature/user-authentication # Git 2.23+ # List branches git branch git branch -a # Include remote branches git branch -r # Remote branches only git branch -v # Show last commit # Switch between branches git checkout main git switch main # Git 2.23+ # Rename branch git branch -m old-name new-name git branch -m feature/user-auth feature/user-authentication # Delete local branch git branch -d feature-branch # Safe delete (merged) git branch -D feature-branch # Force delete # Merge branches git checkout main git merge feature/user-authentication # Merge with no fast-forward git merge --no-ff feature/user-authentication # Abort merge git merge --abort # Resolve merge conflicts # Edit conflicted files, then: git add conflicted-file.txt git commit -m "Resolve merge conflicts" # Rebase branches git checkout feature-branch git rebase main # Interactive rebase git rebase -i HEAD~3 # Abort rebase git rebase --abort # Continue rebase after resolving conflicts git rebase --continue # Cherry-pick commits git cherry-pick commit-hash git cherry-pick commit1..commit3 # Stash changes git stash git stash push -m "Work in progress" # List stashes git stash list # Apply stash git stash apply git stash pop # Apply and remove # Apply specific stash git stash apply stash@{0} # Drop stash git stash drop stash@{0} git stash clear # Remove all stashes

Git Flow Workflow

# Install Git Flow (if not already installed) # macOS: brew install git-flow # Ubuntu: sudo apt-get install git-flow # Initialize Git Flow git flow init # Start a new feature git flow feature start feature/new-dashboard # Finish a feature (merge to develop) git flow feature finish feature/new-dashboard # Start a release git flow release start v1.2.0 # Finish a release (merge to main and develop, tag) git flow release finish v1.2.0 # Start a hotfix git flow hotfix start hotfix/critical-bug # Finish a hotfix git flow hotfix finish hotfix/critical-bug # Manual Git Flow without git-flow tool # Create develop branch git checkout -b develop main # Create feature branch git checkout -b feature/new-dashboard develop # Complete feature git checkout develop git merge --no-ff feature/new-dashboard git branch -d feature/new-dashboard # Create release branch git checkout -b release/v1.2.0 develop # Complete release git checkout main git merge --no-ff release/v1.2.0 git tag -a v1.2.0 -m "Release version 1.2.0" git checkout develop git merge --no-ff release/v1.2.0 git branch -d release/v1.2.0 # Create hotfix branch git checkout -b hotfix/critical-bug main # Complete hotfix git checkout main git merge --no-ff hotfix/critical-bug git tag -a v1.2.1 -m "Hotfix version 1.2.1" git checkout develop git merge --no-ff hotfix/critical-bug git branch -d hotfix/critical-bug

Best Practices

  • ✅ Always write meaningful commit messages
  • ✅ Use branching strategies appropriate for your team
  • ✅ Pull frequently and push often
  • ✅ Review code before merging
  • ✅ Keep commits small and focused
  • ✅ Use .gitignore to exclude unnecessary files
  • ✅ Protect important branches with branch protection rules
  • ✅ Automate testing and deployment with CI/CD
